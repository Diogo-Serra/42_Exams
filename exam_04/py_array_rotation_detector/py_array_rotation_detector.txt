# Array Rotation Detector
 
## Description
 
Write a Python function that takes two lists as parameters and determines whether the second list is a rotation of the first, either to the left or to the right.
 
A rotation shifts the elements of a list circularly. For example, shifting `[1, 2, 3]` to the right by one position results in `[3, 1, 2]`.
 
## Function Signature
 
```python
def array_rotation_detector(arr1: list, arr2: list) -> bool:
```
 
## Rules
 
- Return `True` if `arr2` is a rotation of `arr1`, and `False` otherwise.
- If the lists have different lengths, they cannot be rotations of each other.
- Two empty lists are considered rotations of each other.
## Examples
 
| Call | Output |
| --- | --- |
| `array_rotation_detector([1, 2, 3, 4, 5], [4, 5, 1, 2, 3])` | `True` |
| `array_rotation_detector([1, 2, 3, 4, 5], [5, 1, 2, 3, 4])` | `True` |
| `array_rotation_detector([1, 2, 3], [3, 2, 1])` | `False` |
| `array_rotation_detector([1, 2], [1, 2, 3])` | `False` |
| `array_rotation_detector([], [])` | `True` |
 
## Solution
 
```python
def array_rotation_detector(arr1: list, arr2: list) -> bool:
    """Check whether arr2 is a circular rotation of arr1.
 
    Args:
        arr1: The reference list.
        arr2: The list to test.
 
    Returns:
        True if arr2 can be obtained by rotating arr1 left or right,
        False otherwise.
    """
    if len(arr1) != len(arr2):
        return False
    if not arr1:
        return True
 
    for shift in range(len(arr1)):
        if arr1[shift:] + arr1[:shift] == arr2:
            return True
    return False
```
 
## Explanation
 
1. Lists of different lengths can never be rotations of each other, so the function returns `False` immediately.
2. Two empty lists are rotations of each other, so the function returns `True`.
3. Otherwise, the function builds every possible left rotation of `arr1` and compares it with `arr2`. A right rotation by `k` positions is the same as a left rotation by `n - k` positions, so checking all left shifts covers both directions.
## Complexity
 
- **Time:** O(n²), since there are `n` shifts and each comparison costs O(n).
- **Space:** O(n) for each temporary rotated list.
## Notes
 
This approach works with any list elements, including unhashable ones such as nested lists, because it relies only on equality comparison. A linear-time version is possible by searching for `arr2` as a sublist of `arr1 + arr1` with a pattern-matching algorithm such as KMP.
